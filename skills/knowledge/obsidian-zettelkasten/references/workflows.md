# Learning workflows

## Guided mode

1. Read the supplied source/excerpt and retain locators. For inaccessible material, state the limit and use supplied text without claiming verification. A user observation or experiment can substitute for a publication.
2. Obtain the user's own explanation if not already supplied. For broad material focus on a selected mechanism/question. Do not repeatedly request an explanation already given.
3. Compare explanation and evidence. Identify sound understanding, missing conditions and misconceptions. Discuss central errors with a small example/question before finalizing. Preserve helpful logic and analogies; correct false ones. Silence does not establish agreement with a correction.
4. Search titles, aliases, opening text and relevant maps for overlap; inspect the best matches, expanding as ambiguity warrants.
5. Present the short proposal below and wait for discussion/approval. No full note texts or writes yet.
6. Write only the approved changes. Verify files and links; report outcomes and unresolved questions.

If the user cannot explain yet, help them with a focused question/example/experiment. Propose a draft preserving their current explanation and a specific uncertainty. Do not replace their participation with a model explanation and label it human-grounded.

## Proposal shape

| Thought | Action | Reason and intended connection |
| --- | --- | --- |
| A specific thought | Create / update / draft / leave in source | Why useful; real existing target or approved new thought; substantive corrections. |

Include changes to maps, source records and style profiles. Refer to actual existing paths for updates. This is an illustrative format, not permission to write example notes. Approval covers only the concrete agreed scope; newly needed thoughts require another proposal. Do not ask again for already approved identical changes.

## Thought selection

Retain mechanisms, corrected misunderstandings, useful distinctions, decision support and developments of existing thoughts. Familiar concepts qualify when useful to this learner; original discoveries are not required. No fixed number of notes per source. Lookup-only syntax can remain in documentation.

Prefer one coherent thought to splitting every supporting fact. Separate an idea when independently useful or needing distinct connections. Preserve context and alternative explanations in management or other contextual fields. Mark cross-domain analogies as analogies, not evidence of equivalence. Do not force connections.

## Direct mode

Read style calibration and verify readiness from evidence, not raw count. If unready, state what is missing and continue guided work. For a ready mode select and read 3–5 relevant accepted human-grounded references. Read source evidence, search existing thoughts, propose changes and wait just as in guided mode. After approval, write in the evidenced style without claiming the user explained or mastered it. New explanatory demands may need guided calibration even while direct mode remains usable elsewhere.

## Maintenance

Propose factual corrections and inspect affected claims; improve existing formulations in place; separate independently useful ideas. Preserve IDs, user contributions and links. Record source disagreements with conditions and open questions rather than invented reconciliation. Isolated notes may remain isolated when no genuine relationship exists. A useful cluster may justify a navigation note, not mandatory reclassification.

## Learning review

When asked to review, offer recall before revealing the explanation, prediction, comparison, application or a counterexample. Adapt to time and subject. No mandatory quiz or spaced-repetition system on every note. Record learning difficulties only when requested or under agreed review tracking. Saved notes do not establish mastery.

## Verification

Match actual changes to the approved list. Check schema, unique new IDs, real link targets, block references and affected backlinks after moves/renames. No whole-vault rewrite for a local edit. Structured imports need stable identity, a representative preview and collision checks; batches do not bypass guided input or approval.

Report creations, updates, drafts, deliberately omitted material and source-access limits. Do not silently change unrelated notes, graph settings or calibration evidence.
